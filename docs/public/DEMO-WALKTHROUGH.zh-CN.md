# NexusScribe 验收演示指南

[English](DEMO-WALKTHROUGH.md) · [简体中文](DEMO-WALKTHROUGH.zh-CN.md)

本指南展示当前原型中的作者决定、版本保护与本地恢复。分为两条独立路径：零模型调用接受手写章节，以及使用合成响应自动回放模型辅助界面。两条路径都只使用虚构稿件。演示完成只能证明相应流程检查通过，不能证明真实 agent 的文学质量、通用语义可靠性或生产级持久化。

## 以默认离线模式启动

需要 Node.js 22.12+ 和 npm。在包含演示命令的仓库目录执行：

```sh
npm ci
npm start
```

在运行程序的机器上，用浏览器打开 **http://127.0.0.1:5173**。前端和 API 都绑定本机回环地址，API 使用 `8787` 端口。保留默认离线模板模式，无需账户或供应商密钥。如果当前终端此前配置过真实模型，请先关闭 `NEXUS_LIVE_ENABLED` 和 `NEXUS_OVERAGE_CONFIRMED_OFF`，再启动。程序不会自动加载 `.env` 文件。

这里的“离线”指演示期间不调用外部模型。安装 npm 依赖或 Playwright 浏览器，在没有缓存时仍可能需要网络。启动应用不会发布网站，也不会创建云备份。

另开一个终端，明确执行样例准备命令：

```sh
npm run demo:prepare
```

命令在本地 `demo-output/` 下生成：

- `sample-start.json`：**窗边的信 · 离线验收样例**，含已保存、等待分类的作者示例正文，没有已确认 Canon
- `sample-canon-blocked.json`：**窗边的信 · 设定阻塞样例**，含一条已确认事实和已本地分类、但与之冲突的正文

这些文件是生成的虚构样例，不是用户稿件。准备命令不会把它们自动导入浏览器。`demo-output/`、生成的截图及工作区检查点都不应提交到仓库。如果已在应用中写作，建议使用独立浏览器配置进行演示，并先导出自己的作品。

## 路径 A 零模型调用接受作者章节

下面加粗文字与界面控件一致。本路径不要选择真实模型模式。

1. 点击 **导入备份**，选择 `demo-output/sample-start.json`。核对 **备份导入预览**，再点击 **确认作为新项目导入**。导入会创建新项目，不覆盖已有项目。
2. 打开第一章，查看 **章节正文**。第一次演示保留示例原文，不做修改。
3. 点击 **作者分类保存 · 不调用模型**，在 **确认改文类型** 中选择 **仅局部表达，不更新设定**。查看补丁，再点击 **确认并提交状态**。这是作者作出的分类，程序没有自动证明正文不影响语义。保存及提交分类本身还不会接受章节。
4. 点击 **准备手写稿 · 不提取记忆**。候选应保留精确的已保存正文，标明作者来源及原正文版本，并明确跳过提取、选择 0 条候选记忆。准备候选不等于接受。
5. 点击 **审查候选稿**。没有已确认 Canon 时，只进行本地结构与版本检查。应明确显示语义未经评估；这一步没有模型审阅。
6. 点击 **接受此版本**。在 **确认接受候选稿与已选记忆** 中核对章节、原正文版本、候选版本、文本校验值和 0 记忆选择。先点击一次 **返回核对**，确认打开和关闭窗口不会接受正文。再次打开，然后点击 **确认接受正文与所选记忆**。
7. 刷新页面。章节仍应为已接受，正文不变；原始正文版本和接受记录仍然保留，没有新增事件记忆或 Canon 事实。

**本路径的通过条件：** 精确作者正文经历分类、准备、明确接受和刷新后仍然保留；只有最终确认才接受章节；模型调用数为 0。本地结构检查通过时，语义与文学质量仍未经评估。

如果准备或接受被阻塞，检查是否有暂存编辑、待决补丁、存储警告、尚未接受的前一章或已变化的来源版本。不要通过清空浏览器存储来强行通过。如果准备手写候选后又修改了已保存正文，应完成新分类，拒绝旧候选，再准备新稿。旧审阅或旧跳过决定不能授权新正文。

## 导出与导入恢复检查

1. 完成路径 A 后，点击 **导出项目备份**，把下载的 JSON 保存在浏览器存储之外。
2. 通过 **导入备份** 选择该文件，核对预览，先点击一次 **取消导入**，确认当前项目不变。
3. 再次导入同一文件，点击 **确认作为新项目导入**。新项目应保留已接受章节、精确正文、原正文版本及接受记录。通过 **切换项目** 确认原项目仍可使用。
4. 刷新，再次检查新导入项目的已接受章节。

已接受备份与待定稿的授权不同。导入待定稿时，证据会保留，但旧审阅、跳过提取及采用建议的授权会撤销。接受前须重新明确选择提取路径并完成必要的新审阅。导入不等于再次认可语义。

如果出现 **尚未安全保存**，保持窗口打开，先通过 **导出当前内容（含暂存编辑）** 保存可读内容，解决存储问题后再 **重试保存**。重试保存成功不会自动重放此前失败的接受确认。独立存储自动化测试会注入配额失败及主存储损坏；不要损坏真实浏览器数据来复现。限制详见[本地备份与恢复](BACKUP-RECOVERY.md)，包括工作区共用 2 MiB 上限，以及清除站点数据会删除所有本地副本。

## 有 Canon 时必须阻止离线绕过

1. 通过预览，把 `demo-output/sample-canon-blocked.json` 导入为另一个新项目。
2. 查看已确认事实 **陆遥从未见过寄信人。** 和冲突正文 **陆遥认出寄信人的脸，说：“我们昨天见过。”**。样例已完成本地分类与同步，点击 **准备手写稿 · 不提取记忆** 创建作者来源候选。
3. 保持离线模板模式，点击 **审查候选稿**。确认缺少新的模型审阅及既有逐项设定门禁时，候选无法最终接受；原已确认事实保持不变。
4. 此手动场景到阻塞处结束。本指南不执行真实审阅。

**本路径的通过条件：** 手写来源和 0 记忆选择都不能绕过当前版本所需的模型审阅。这个阻塞本身并不证明模型已识别矛盾。在另行启用的真实模式中，审阅是明确的模型请求，可能消耗一次调用；冲突或未知判断仍需解决。模型判断始终是可能误判的建议。

## 路径 B 使用合成响应回放模型辅助界面

本路径由 Playwright 操作可见的创作控件。模型传输由测试模拟，浏览器的非本地请求被阻断。由于测试覆盖该分支，界面可能显示真实模型模式的标签；这不代表访问了真实供应商，也不需要 API 密钥。

首次使用时安装 Chromium，然后在仓库根目录运行精选验收回放：

```sh
npx playwright install chromium
npm run demo:acceptance
```

Linux 环境还需 Chromium 的系统依赖，可使用已维护的 CI 镜像或 `npx playwright install --with-deps chromium`。浏览器无法启动或安装失败属于环境阻塞，不算演示通过。

回放覆盖以下检查点：

1. 虚构故事灵感 → 访谈 → 可编辑的故事约定与章节规划 → 明确确认
2. 合成生成正文保存为候选，不自动接受
3. 明确请求改稿 → 独立建议 → 与保留的模型原文比较
4. 在 **待采用正文** 中本地编辑 → **确认采用并使旧审阅失效**；新采用版本记录为 `explicit_author_edit`，原始模型结果保持不变
5. **不提取记忆 · 仅保留正文** → 绑定版本的 **确认不提取记忆**；0 条新记忆来自作者决定，不是假造的成功提取
6. 对精确编辑后候选完成新的模拟整章审阅 → 最后明确接受
7. 下一章生成请求以 `accepted_manuscript` 来源角色包含已接受原文，即使新增事件记忆为 0

带名称的截图、`acceptance-receipt.json` 和 `accepted-backup.json` 写入 `test-results/` 下相应的 Playwright 测试目录。应同时核对命令结果与产物；前面某一步的截图不能证明后续接受成功。把这些文件作为本地测试证据保留，不要把截图、导出项目或浏览器工作区提交到仓库。

**本路径的通过条件：** 所有脚本断言完成，当前版本所需确认仍然有效，原始模型证据不变，已接受正文进入下一次请求，且没有真实调用。模拟审阅响应是预先编写的测试数据。此回放不评估模型能否写作、改稿、识别矛盾或判断引文支持。

更广泛的离线检查可执行 `npm run check` 和 `npm run test:e2e`。[手写章节](../../e2e/manual-chapter.spec.js)、[仅正文接受](../../e2e/prose-only.spec.js)、[改稿](../../e2e/author-revision.spec.js)及[存储](../../e2e/storage.spec.js)套件还覆盖过期状态、取消、导入及保存失败边界。自动化通过数只适用于精确受测源码，不能替代对生成截图的检查。

## 真实质量失败仍然是失败

保留的[按作者意见改稿试验](../../eval/AUTHOR-REVISION-RESULTS.md)在一次调用后停止。它达到 396 汉字、5 段，修复了不透明纸盒问题，却新增紧邻的“没再敲／敲了三下”动作矛盾。细读门禁失败，没有继续提取或审阅。离线回放中的模拟作者修正不会改写该模型原文或失败结果。

保留的[多章试验](../../eval/MULTICHAPTER-RESULTS.md)在第八次调用后停止。第一章有一个自身引文未包含的细节被误报为 `supported`；第二章首条候选的引文不匹配被正确拒绝。没有建立完整三章链路或文学质量通过结论，两篇生成正文也都超出目标字数和段数。原始报告与证据不变；其中部分历史建议描述的是试验当时的产品状态。

## 功能冻结与下一步评测边界

本包把现有流程整理为可复现的演示，不新增运行时功能，也不启动真实试验。核对验收证据期间继续冻结功能。

下一项有价值的工作是预注册的**因果连续性与引文支持评测设计**，任何执行均须另行获得明确授权。先冻结精确源码、虚构输入、请求范围、调用上限、停止规则与证据保留方案。因果检查要覆盖动作先后、物理可见性、物件归属，以及修复一个问题后是否新增矛盾。引文支持检查须只凭该条自身引文判断完整陈述，覆盖缺失细节、归属、否定与时间范围；保留已知误报反例和明确的正、负对照。

分别报告传输／结构通过、确定性计数、作者决定、语义判断及文学评价。保留失败，不通过不断重试挑出通过结果。任何真实试验都需要独立授权和执行证据，本文件及演示命令都不授予该权限。通用语义可靠性、长篇连续性和真实 agent 的文学质量仍未解决。
