# NexusScribe

**从一句灵感开始，一章一章，把故事写成你想要的样子。**

[English](README.md) · [简体中文](README.zh-CN.md)

NexusScribe 是一个以**版本化叙事记忆**为核心、由作者掌握关键决定的小说创作工作台。从灵感到故事约定与章节规划，从候选正文到审阅与接受，再到修改后的记忆更新，让已确认的创作决定影响后续写作。

当前原型面向中文小说，采用中文界面。本地运行，默认使用离线模板，也可显式启用服务端模型适配。

> **项目状态：可运行原型。** 离线模板用于演示工作流；真实供应商连通性、写作质量与成本尚未完成端到端验证。固定案例中的一致性规则不能证明任意故事都能保持语义正确。

## 为什么需要叙事记忆？

一处正文修改，可能改变人物关系、使后续场景失去前提，或影响角色知道什么。NexusScribe 将正文、变更提案与已确认的故事状态分别保存，让这些影响可以检查、决定和追溯。

- **修改可追溯：** 正文版本和记忆补丁关联精确原文证据
- **提交由作者决定：** 新事实与候选章节必须经过明确接受
- **选择性复核：** 预置故事展示依赖检查与替代知识来源
- **草稿隔离：** 被拒绝的候选不会进入已确认的故事事实，即 Canon
- **版本保护：** 来源变化后，旧提案和旧审阅不能继续套用
- **补偿撤销：** 撤销会新增历史记录；存在后续依赖时阻止不安全的逆操作

## 完整创作流程

1. **探索灵感：** 通过针对性访谈，明确人物、基调、视角、目标与创作边界。
2. **确认故事约定：** 编辑并确认故事约定和三章大纲。
3. **创作章节：** 生成候选正文，修改文字，检查拟提交事件与审阅结果。
4. **接受或拒绝：** 接受后更新故事状态；拒绝的候选留在 Canon 之外。
5. **根据证据修订：** 保存正文修改，检查记忆更新提案及其原文片段，再明确确认。
6. **继续与保存：** 切换章节和项目，查看版本记录，导出正文或 JSON 备份。

离线模式支持三章模板流程。服务端适配已实现访谈、故事规划、章节生成、修改解释和章节审阅五类模型操作。模型输出始终需要经过提案与确认边界。

## 快速开始

可运行演示目前位于 [`feat/nexusscribe-demo`](https://github.com/logan-suu/NexusScribe/tree/feat/nexusscribe-demo) 分支与 [PR #1](https://github.com/logan-suu/NexusScribe/pull/1)；合并前请使用该分支。

需要 **Node.js 22.12+** 和 npm。在包含本演示程序的仓库目录执行：

```sh
npm ci
npm start
```

在运行程序的机器上打开 **http://127.0.0.1:5173**。前端与 API 均绑定本机回环地址，API 使用 `8787` 端口。离线模式无需账号、API 密钥或外部模型调用。

### 试一次会影响后续故事的修改

打开预置故事 **「雾港来信」**：

1. 在第二章选择 **「插入设定修改」**，然后点击 **「保存并分析」**。
2. 检查人物关系变化、原文证据与受影响的计划，再确认提交。
3. 观察陌生关系前提失效，而风暴等其他计划按各自条件单独复核。
4. 生成候选稿，先审阅，再接受或拒绝。
5. 在第一章删除电话来源：仍然有效的纸条可以继续支持角色认知。
6. 查看版本记录与补偿撤销，检查已有后续依赖时的撤销保护。

该案例用于展示特定机制。自建项目具有结构保护与模型辅助提案，但不具备任意故事的一致性证明。

## 可选：连接模型

浏览器通过同源 API 发起操作，**密钥与外部请求均由服务端进程管理**。真实模式会将对应操作的输入，包括相关正文与故事上下文，发送给配置的供应商。使用私人稿件前，请先核对其条款与数据处理方式。

仓库中的 [`.env.example`](.env.example) 提供以下不含密钥的参考配置：

```dotenv
NEXUS_API_BASE_URL=https://opencode.ai/zen/go/v1
NEXUS_API_MODEL=deepseek-v4.1-flash
NEXUS_LIVE_ENABLED=false
NEXUS_OVERAGE_CONFIRMED_OFF=false
NEXUS_MAX_OUTPUT_TOKENS=1200
NEXUS_MAX_CALLS=10
```

这组 OpenCode Go 地址与模型 ID **是配置示例，不代表账户已具备使用权限或已完成生产验收**。一次明确设置 `NEXUS_REASONING_EFFORT=low`、上限 3000 tokens 的合成故事规划测试已通过，但后续 low 请求仍发生截断，因此不代表稳定完成、所有创作环节或任意小说质量已验证。详见[模型兼容性证据](docs/public/MODEL-COMPATIBILITY.md)。程序不会自动加载 `.env` 文件。

启用真实模式：

1. 核对供应商地址、模型权限、适用条款和账户额度，并在供应商账户中检查余额／超额扣费已关闭。
2. 通过安全的**服务端进程环境**提供配置与 `NEXUS_API_KEY`。完成上述检查后，才将 `NEXUS_LIVE_ENABLED` 和 `NEXUS_OVERAGE_CONFIRMED_OFF` 设为 `true`。
3. 启动或重启 API，在界面 **「模型」** 中选择真实模式。

不要把密钥放进 `VITE_` 变量、浏览器、聊天、源代码、共享文件或命令历史。界面没有密钥输入字段；应用也不会验证或更改供应商账户的超额扣费设置。

### 请求与费用边界

- 默认输出上限 `1200` tokens，可配置至 `3000`
- 可显式设置 `NEXUS_REASONING_EFFORT=low`，或单独设置 `NEXUS_THINKING_MODE=disabled`，不能同时使用。不设置则保留供应商默认行为；Go 的 thinking-disabled 路径仍在兼容性验证中，不支持的值会被拒绝
- 每个服务进程默认最多尝试 `10` 次，可配置至 `30` 次
- 最多两个并发请求，每分钟最多六次尝试
- 默认超时 30 秒；请求与响应各限 128 KiB
- 不自动重试、不跟随上游重定向、不静默回退到模板

供应商调用失败也会消耗进程内次数，重启服务会重置计数。**这些限制不等于金额预算或供应商账单上限。** API 不记录正文或密钥，也不透传上游原始错误详情。

## 审查与提交保护

- 提案绑定项目、状态版本与正文 revision。
- 确认记忆更新前，引用片段必须精确对应当前正文。
- 作者可以明确替代已有事实，同时保留稳定 ID 与旧版本历史。
- 真实模型稿必须完成结构检查和当前版本的模型审阅。错误级问题阻止接受；警告保留供作者判断。
- 编辑候选稿会使旧审阅失效。模型审阅是未经独立验证的建议，不能证明内容正确。
- 保存正文与更新叙事记忆是两个步骤；不支持的语义修改不能被默认为已同步。

## 架构

```text
中文创作工作台（React + Vite）
  ├─ 创作流程：访谈 → 故事约定 → 大纲 → 候选章节
  ├─ 叙事内核：证据、版本、依赖、审查与提交
  ├─ 本地存储：工作区、历史、正文／JSON 导出
  └─ 同源模型客户端
       └─ Node.js 网关：校验、密钥与请求限制
            └─ HTTPS OpenAI-compatible 供应商（显式启用）
```

| 目录或文件 | 职责 |
| --- | --- |
| `src/domain/` | 故事状态、补丁、证据、依赖、草稿隔离与审查保护 |
| `src/authoring/` | 访谈、故事约定、大纲、模板与真实模型流程 |
| `src/adapters/` | 浏览器侧模型调用边界 |
| `src/components/` | 中文创作工作台 |
| `src/storage.js` | 本地保存与导出 |
| `server/` | 供应商协议、schema、超时与请求限制 |
| `tests/` 与 `scripts/` | 叙事内核、模型适配和 UI 工作流检查 |

详见[运行时架构](docs/public/ARCHITECTURE.md)与[完整产品蓝图](docs/public/NexusScribe-blueprint.md)。蓝图包含规划中的能力，不代表全部已实现。

## 开发与验证

```sh
npm run dev           # 仅前端，端口 5173
npm run server        # 仅 API，端口 8787
npm test              # 领域、契约与假供应商测试
npm run test:ui       # 离线 DOM 工作流检查
npm run test:ui:live  # 假模型五环节 UI 工作流
npm run check         # 上述检查与 production build
npm run build
npm run preview       # 构建预览，端口 4173；API 需另行启动
```

安装 Playwright 所需的 Chromium 后，可单独运行浏览器测试：

```sh
npx playwright install chromium
npm run test:e2e
```

浏览器测试覆盖桌面与移动尺寸的 Chromium 视口，使用离线内容和模拟 API 响应，不包含在 `npm run check` 中。Linux CI 还需要浏览器系统依赖（`npx playwright install --with-deps chromium`）。

这些自动化测试不产生付费模型调用。测试通过不代表真实供应商可用、语义质量达标、跨浏览器兼容或已完成视觉验收。真实服务冒烟测试需要另行明确启用；GitHub 仓库中的 secret 不会自动配置本地运行或已部署的应用。

## 当前限制与后续方向

- **单作者、本地存储：** 没有服务端数据库、账号鉴权、云备份或多人并发保证。过时窗口检测不是数据库事务。
- **备份仅支持导出：** 清理浏览器站点数据可能丢失工作区。请定期导出；目前没有备份导入界面。
- **叙事推理范围有限：** 任意设定的语义冲突／替代推理与通用知识传递路径证明尚未完成。
- **仍需进一步验收：** 真实供应商测试、长篇评测、基线比较、跨浏览器覆盖与生产安全审查仍需推进。

后续方向包括验证真实模型行为与写作质量、将修改与证据处理扩展到固定案例之外，以及加强持久化与恢复。这些是发展目标，并非已交付能力或交付时间承诺。
