# NexusScribe

**从一句灵感开始，一章一章，把故事写成你想要的样子。**

[English](README.md) · [简体中文](README.zh-CN.md)

NexusScribe 是一个以**版本化叙事记忆**为核心、由作者掌握关键决定的小说创作工作台。从灵感到故事约定与章节规划，从候选正文到审阅与接受，再到修改后的记忆更新，让已确认的创作决定影响后续写作。

当前原型面向中文小说，采用中文界面。本地运行，默认使用离线模板，也可显式启用服务端模型适配。

> **项目状态：可运行原型。** 历史真实测试仅适用于记录中的修订。当前采用先独立保存正文、再提取候选记忆的链路，验证结果单独记录；文学质量、通用语义可靠性与实际账单费用尚无结论。见[验收记录](docs/public/ACCEPTANCE.md)。

## 为什么需要叙事记忆？

一处正文修改，可能改变人物关系、使后续场景失去前提，或影响角色知道什么。NexusScribe 将正文、变更提案与已确认的故事状态分别保存，让这些影响可以检查、决定和追溯。

- **修改可追溯：** 正文版本和记忆补丁关联精确原文证据
- **提交由作者决定：** 新事实与候选章节必须经过明确接受
- **选择性复核：** 预置故事展示依赖检查与替代知识来源
- **草稿隔离：** 被拒绝的候选不会进入已确认的故事事实，即 Canon
- **版本保护：** 来源变化后，旧提案和旧审阅不能继续套用
- **补偿撤销：** 撤销会新增历史记录；存在后续依赖时阻止不安全的逆操作

## 完整创作流程

1. **探索灵感：** 通过针对性访谈，明确人物、基调、视角、目标与创作边界。
2. **确认故事约定：** 编辑并确认故事约定和三章大纲。
3. **创作章节：** 先生成并保存原始候选正文，再提取候选记忆，或明确选择不提取；完成当前审查后决定是否接受。改稿后须重新选择提取方式与审查。
4. **逐条选择，再接受：** 每条候选记忆明确保留或拒绝；可单独请求一次隔离核对，只传送这条完整标签与自身引文。未知／不支持的条目只能填写作者理由后明确覆盖保留。最后确认只提交选中记忆；全部拒绝已提取候选或明确跳过提取，都可在当前审查后以 0 条新记忆接受正文。
5. **根据证据修订：** 保存正文修改，检查记忆更新提案及其原文片段，再明确确认。
6. **继续与保存：** 切换章节和项目，查看版本记录，导出正文或 JSON 备份。

离线模式支持三章模板流程。正常真实模型链路包含访谈、规划、正文生成、独立记忆提取、修改解释、整章审阅和另行请求的单条隔离核对；保留旧版严格生成接口供兼容与对照。正文与整章审阅为两次基础请求；可选提取再增加一次，明确请求的每条隔离核对再增加一次。选择跳过不会撤销之前的调用，不承诺零费用或时延优势。模型输出始终需要经过提案与确认边界。

## 快速开始

集成完成后使用开发分支 `dev_v1.0`；审阅未合入改动时使用对应 PR 的提交。`main` 保留为发布边界，克隆仓库不会创建公开在线应用。

需要 **Node.js 22.12+** 和 npm。在包含本演示程序的仓库目录执行：

```sh
npm ci
npm start
```

在运行程序的机器上打开 **http://127.0.0.1:5173**。前端与 API 均绑定本机回环地址，API 使用 `8787` 端口。离线模式无需账号、API 密钥或外部模型调用。

### 试一次会影响后续故事的修改

打开预置故事 **「雾港来信」**：

1. 在第二章选择 **「插入设定修改」**，然后点击 **「保存并分析」**。
2. 检查人物关系变化、原文证据与受影响的计划，再确认提交。
3. 观察陌生关系前提失效，而风暴等其他计划按各自条件单独复核。
4. 生成候选稿，先审阅，再接受或拒绝。
5. 在第一章删除电话来源：仍然有效的纸条可以继续支持角色认知。
6. 查看版本记录与补偿撤销，检查已有后续依赖时的撤销保护。

该案例用于展示特定机制。自建项目具有结构保护与模型辅助提案，但不具备任意故事的一致性证明。

## 可选：连接模型

浏览器通过同源 API 发起操作，**密钥与外部请求均由服务端进程管理**。真实模式会将对应操作的输入，包括相关正文与故事上下文，发送给配置的供应商。使用私人稿件前，请先核对其条款与数据处理方式。

仓库中的 [`.env.example`](.env.example) 提供以下不含密钥的参考配置：

```dotenv
NEXUS_API_BASE_URL=https://opencode.ai/zen/go/v1
NEXUS_API_MODEL=deepseek-v4.1-flash
NEXUS_LIVE_ENABLED=false
NEXUS_OVERAGE_CONFIRMED_OFF=false
NEXUS_MAX_OUTPUT_TOKENS=1200
NEXUS_MAX_CALLS=10
```

这组 OpenCode Go 地址与模型 ID **是配置示例，不代表账户已具备使用权限或已完成生产验收**。一次明确设置 `NEXUS_REASONING_EFFORT=low`、上限 3000 tokens 的合成故事规划测试已通过，但后续 low 请求仍发生截断。随后单独使用 `NEXUS_THINKING_MODE=disabled` 请求、无 effort 字段、相同输出上限的合成五环节测试通过，并完成暂存、拒稿、接受和补偿撤销验证。这是有界样例证据，不是任意小说质量保证。详见[模型兼容性证据](docs/public/MODEL-COMPATIBILITY.md)。程序不会自动加载 `.env` 文件。

启用真实模式：

1. 核对供应商地址、模型权限、适用条款和账户额度，并在供应商账户中检查余额／超额扣费已关闭。
2. 通过安全的**服务端进程环境**提供配置与 `NEXUS_API_KEY`。完成上述检查后，才将 `NEXUS_LIVE_ENABLED` 和 `NEXUS_OVERAGE_CONFIRMED_OFF` 设为 `true`。
3. 启动或重启 API，在界面 **「模型」** 中选择真实模式。

不要把密钥放进 `VITE_` 变量、浏览器、聊天、源代码、共享文件或命令历史。界面没有密钥输入字段；应用也不会验证或更改供应商账户的超额扣费设置。

### 请求与费用边界

- 默认输出上限 `1200` tokens，可配置至 `3000`
- 可显式设置 `NEXUS_REASONING_EFFORT=low`，或单独设置 `NEXUS_THINKING_MODE=disabled`，不能同时使用。不设置则保留供应商默认行为；Go 的 thinking-disabled 请求配置已通过有界合成测试，但不能据此证明内部推理为零；不支持的值会被拒绝
- 每个服务进程默认最多尝试 `10` 次，可配置至 `30` 次
- 最多两个并发请求，每分钟最多六次尝试
- 默认超时 30 秒；请求与响应各限 128 KiB
- 不自动重试、不跟随上游重定向、不静默回退到模板

供应商调用失败也会消耗进程内次数，重启服务会重置计数。**这些限制不等于金额预算或供应商账单上限。** API 不记录正文或密钥，也不透传上游原始错误详情。

## 审查与提交保护

- 提案绑定项目、状态版本与正文 revision。
- 确认记忆更新前，引用片段必须精确对应当前正文。
- 作者可以明确替代已有事实，同时保留稳定 ID 与旧版本历史。
- 真实模型稿必须完成结构检查和当前版本的模型审阅。错误级问题阻止接受；警告保留供作者判断。
- 逐条决定绑定精确候选正文、提取批次与审阅；改稿、重新提取或重审使旧授权失效，原始候选与决定历史保留。模型判断“支持”仍不证明真实。
- 缺失判断按未知阻塞；作者覆盖保留须明确填写理由，原标签、引文与模型判断不被改写，设定冲突及一般 error 门禁仍有效。
- 保存正文与更新叙事记忆是两个步骤；不支持的语义修改不能被默认为已同步。

## 架构

```text
中文创作工作台（React + Vite）
  ├─ 创作流程：访谈 → 故事约定 → 大纲 → 候选章节
  ├─ 叙事内核：证据、版本、依赖、审查与提交
  ├─ 本地存储：工作区、历史、正文／JSON 导出
  └─ 同源模型客户端
```

## 当前限制与后续方向

- **单作者、本地存储：** 没有服务端数据库、账号鉴权、云备份或多人并发保证。过时窗口检测不是数据库事务。
- **有限备份恢复：** JSON 备份经预览和明确确认后作为新项目导入。正文保存失败会保留内存编辑并提供导出/重试；损坏主存储可在保留原始数据后确认恢复上一份可读副本。清理站点数据仍会丢失全部本地副本，请定期导出。详见[备份与恢复边界](docs/public/BACKUP-RECOVERY.md)。
- **叙事推理范围有限：** 任意设定的语义冲突／替代推理与通用知识传递路径证明尚未完成。
- **仍需进一步验收：** 有界真实供应商／领域样例已通过；更广泛的供应商稳定性、长篇评测、基线比较、跨浏览器覆盖与生产安全审查仍需推进。

后续方向包括验证真实模型行为与写作质量、将修改与证据处理扩展到固定案例之外，以及加强持久化与恢复。这些是发展目标，并非已交付能力或交付时间承诺。

### 请求控制与用量

模型任务显示当前动作及等待、返回、失败状态，不使用虚构进度百分比。取消会停止浏览器等待，并请求本地网关中止对应上游请求；断开连接或关闭新建故事也会中止。取消不保证供应商停止处理或计费。不会自动重试；检查错误后，使用原动作按钮手动重试。

结果绑定发起请求时的项目、正文与候选版本、暂存编辑、章节选择和运行模式。期间发生变化则不采用返回结果；旧请求不会清除或覆盖新请求。刷新页面不会恢复模型任务，原有正文及暂存编辑仍按既有方式保存。失败或取消不会接受候选稿或提交故事记忆。

用量面板仅展示服务端供应商报告的数值 token 计数；未报告及取消、失败后不可获取的计数显示“未知”。不推算总计、费用或账单上限。离线模拟测试不能证明真实模型质量或实际计费行为。

## 正文先保存，记忆后提取

模型无需同时输出正文 JSON、章节 ID 与记忆。程序保管原始正文版本、段落 ID、精确位置和引文；独立提取只提出候选事件。提取失败或取消后正文保留，接受被阻塞；可明确手动重试或确认不提取，再重新审查。提取通过仍不证明语义正确，必须核对来源、完成设定审阅并由作者接受。生成成功但浏览器保存失败时只保留内存副本并提示导出/重试，不冒称已经落盘。

旧质量试验仍为 0 个完整配对；新架构有独立的[9 次上限实验协议](eval/PROSE-PIPELINE-PROTOCOL.md)。契约通过率与文学质量分别报告；不根据结构测试声称写作更好。

首轮新架构实验在第 6 次请求停止，完成 1 组配对：两组新正文/提取均通过结构校验，第二组旧版对照 JSON 解析失败；同时发现一条提取标签超出所引段落的含义。见[完整结果与用量/时延](eval/PROSE-PIPELINE-RESULTS.md)，尚无文学优势或节费结论。

## 逐条候选记忆审阅

默认选择改为程序从当前正文生成的完整段落摘录，附前后文与精确版本／位置。它只证明文字存在，不证明世界真相，也不证明原模型标签的含义。保留任何自由转述都必须另行勾选知情确认并填写作者理由，即使模型判断 `supported` 也不能省略。旧已接受选择仍显示为历史未验证转述；原始标签、引文和判断完整保留。见[原文摘录记忆与迁移](docs/public/QUOTE-GROUNDED-MEMORY.md)。

正文＋整章审阅为两次基础调用，可选提取再加一次；明确核对 K 条候选才增加 K 次可选调用。摘录选择、作者确认转述、全部拒绝均不请求模型。全部拒绝后可最终仅接受正文，无隐藏重试。保留既有版本、取消、预算、保存失败恢复与审计保护；文本存在、作者决定、模型建议是不同证据，不宣称通用语义或文学质量保证。

[首次真实支持审阅](eval/MEMORY-SUPPORT-RESULTS.md)未识别保留的引文不完整反例，随后第二次请求超时，已按协议停止。受测版本中模型误报“支持”会开放普通保留；独立请求修正已在另外批准的四条固定用例中通过预注册预期，并随 PR #9 合入 dev_v1.0；这不代表通用语义准确率。作者核对仍是必要边界。见[隔离核对结果](eval/ISOLATED-MEMORY-SUPPORT-RESULTS.md)与[修正设计](docs/public/ISOLATED-MEMORY-REVIEW.md)。


## 多章续写与恢复

后续上下文包含作者选中的当前有效事件记忆、精确正文及规划来源角色；过期来源会排除并计数，拒绝标签不等于删除正文事实。自建项目按当前章节显示候选，提取／整章审阅结果在保存失败时保留在当前窗口。旧候选可明确更新参考上下文，保留正文后重新提取与审阅。见[行为与限制](docs/public/MULTICHAPTER-CONTINUITY.md)及[保留正文的非盲评细读](eval/RETAINED-PROSE-CLOSE-READING.md)，不据此声称文学优势或长篇连续性已解决。


[首轮真实多章试验](eval/MULTICHAPTER-RESULTS.md)在第八次调用停止：第二章的首条候选被正确拒绝，但第一章此前已出现一次误报支持，模型承认引文缺少地点细节仍放行。两篇保留正文均超出字数和段数目标。四条固定用例通过不能泛化为语义可靠，不宣称三章链路或文学质量验收通过；旧试验 CLI 已停止真实调用，模型判断仅是建议。

## 不重新生成，也能接受自己写好的章节

自建项目中，点击 **作者分类保存 · 不调用模型**，明确改文类型，再审阅并提交补丁。**准备手写稿 · 不提取记忆** 会把已同步的精确正文版本复制为不可改写的作者来源候选，并明确选择 0 条候选记忆；不会生成、提取、请求模型审阅或代替作者接受。仅保存/分类仍不会把章节标为已接受。

- **没有已确认设定时**，**审查候选稿** 只做本地结构与版本检查。最终确认展示章节、原正文版本、候选版本和文本校验值，可以零模型调用完成；语义一致性与文学质量未经评估。
- **有已确认设定时**，现有模型审阅及逐项冲突/未知判断门禁仍然必需。须选择真实模型模式并明确点击审查，可能产生一次模型请求；结果仍是可能误判的建议。准备手写稿或跳过提取不能豁免这些门禁，不承诺所有手写稿都能零调用接受。
- 手写候选的记忆提取可选，须在真实模型模式下另行点击；提取后沿用原文摘录/未验证转述选择规则。**不提取记忆 · 仅保留正文** 会归档旧提取与选择并要求重新审查，记录为“作者跳过”，不冒充模型成功返回空结果。
- 暂存编辑、待决补丁、存储不安全、前章未接受或确认窗口版本变化都会阻塞接受。已接受手写章节改文后，新版本即使完成本地分类也仍需重新接受，才能继续后章。旧手写候选不能通过更新参考上下文覆盖较新的正文：请在章节编辑器修改并分类，拒绝旧稿，再准备新稿。其他上下文变化可明确更新后重审。
- 重载与已接受备份导入保留作者来源、分类记录、正文版本和接受历史。待定候选导入会撤销旧跳过/审阅授权，需要重新明确选择；缺少精确来源审计的历史分类需重新本地分类一次。下一章看到已接受原文及符合条件的作者所选记忆；选择 0 条不会抹去原文内容。

本轮使用离线领域、存储、DOM 与合成浏览器回归验证流程安全，不证明语义可靠或真实模型写作质量；没有新增真实模型试验或发布。

## 按作者意见修改待定模型稿

待定的真实模型正文可填写 **改稿意见**，明确点击 **按意见生成改稿建议 · 1 次模型请求**。程序先检查本次服务进程调用预算，再发送精确候选全文、意见与当前故事上下文，使用原有配置模型请求一次。离线模板、已接受稿与不可改写的手写来源快照不支持此操作。

- 返回独立建议，完整展示前后正文。汉字按 Unicode `Script=Han` 计数；字符按全部 Unicode 码点计数（含空白和换行）；每个非空物理行算一段。计数合规不是文学质量合格
- 采用前再次确认：追加候选新版本，归档并使旧提取、审阅、设定例外与记忆选择失效。不会自动提取、审阅、接受章节或提交记忆；原稿与模型来源仍保留，可随项目备份导出
- 放弃保留原稿和建议历史。原稿、上下文、修改意见变化后，旧建议不能采用；意见改走再改回也不能复用。失败、取消均不自动重试；工作区变化后收到的结果保留为过期记录，不授予采用权限
- 预算缺失/耗尽或存储不安全时不派发。结果已收到但保存失败时保留在当前窗口，可导出或重试保存，无需再次付费请求；恢复前关闭窗口可能丢失未保存结果。重载保留仍然有效的完成建议；中断请求须先明确 **取消中断的改稿请求**，再另行请求。备份导入撤销待定建议采用权限

这个入口与现有 **局部润色** 的两处演示字符串替换，以及解释作者已完成改文的 `interpretRevision` 不同。原有模型仍可能引入新问题。[固定改稿小试验](eval/AUTHOR-REVISION-PROTOCOL.md) 按精确源码 CI 与逐步阅读门禁完成了一次有限试验，该真实调用入口现已停止；流程回归不宣称真实写作质量改善，也不代替作者接受。

[首次按意见改稿试验](eval/AUTHOR-REVISION-RESULTS.md)在一次调用后停止：字数与段数达标（396 汉字、5 段），不透明纸盒的问题修好了，却新增“没再敲”紧接“敲了三下”的动作矛盾。没有继续提取或审阅，也没有重试；真实试验入口已停止。属于有针对性的局部改善，但细读门禁失败，不宣称文学质量通过；原始输出与失败判断均已保留。

### 采用前在本地编辑建议稿

采用确认窗口新增 **待采用正文** 编辑区。作者可先修正或调整建议，与不可改写的模型原文比较，再明确确认，按最终文本新增候选版本。最终稿与模型原文不同，记录 `explicit_author_edit`；原样采用则记录 `explicit_model_adoption`。模型原文、provider/用量和原始计数不变；最终采用记录指向准确的候选版本，保留校验值与计数，并单独核对模型原结果的校验值（只检查结构一致性，不是身份认证或真实性证明），后续编辑或导入备份仍可查看。

可选 **汉字下限 / 汉字上限 / 段数下限 / 段数上限** 仅提供确定性的低于/高于范围提醒。留空即不设限制；值须为非负安全整数，且下限不大于上限。只使用作者明确填写的数值，不从自由文本意见推断，不发送模型。超出范围仍可明确采用；计数不验证含义、因果或文学质量。

编辑区与范围在成功确认前尚未保存。返回、关闭、Escape 或刷新会放弃本地编辑，再次打开从保留的模型原始建议开始。可用 **导出待采用正文** 保存本地文本。若采用时遇到配额/权限保存失败，窗口保留编辑并提供可操作的本地重试保存；重试只恢复工作区保存，随后还需明确确认采用，不会调用模型。现有工作区清洁检查、过期绑定、付费结果保留、导入及旧审阅失效保护继续适用。

离线回归使用已保留的矛盾输出，由测试模拟作者删去“没再敲，”并检查作者编辑来源。这只证明编辑流程；[原失败试验报告](eval/AUTHOR-REVISION-RESULTS.md)、原始输出和历史证据未改写，不宣称模型质量成功，也没有新真实调用、章节接受、发布或部署。


### 模型来源候选也可明确选择只接受正文

待定的独立正文候选，包括作者本地编辑后采用的改稿建议，现在也提供 **不提取记忆 · 仅保留正文**。确认窗口绑定当前版本，先说明提取状态与候选数量；确认后清空当前候选，归档旧提取、引文、选择及审阅，使所有旧审阅与设定例外失效。在途请求须先取消；取消不保证供应商停止计费。失败不会自动成为“成功但没有候选”的结果。

完整路径是 **保存/采用候选 → 明确跳过提取 → 请求新的整章审阅 → 解决设定门禁 → 最后确认接受 → 下一章**。即使没有候选记忆，模型来源正文仍须经过既有模型审阅。最后接受记录准确的候选版本、正文与跳过决定，不再调用模型，也不会把模型稿改标成手写来源或修改已有设定。已接受正文仍进入后续章节原文上下文；0 条新事件记忆不等于没有上下文，也不等于全流程 0 次调用。

编辑或更新参考上下文使旧跳过决定失效；待定备份导入后须重新选择和审阅。返回或关闭确认不改状态；保存失败或另一窗口冲突阻止提交。重新编辑或补偿撤销该已接受章节会移除当前“已接受原文”身份，旧正文、原始改稿建议及审计证据仍保留。

离线领域测试与托管桌面/移动浏览器回归覆盖：保留的失败改稿 → 模拟作者修正 → 新的模拟审阅 → 0 记忆接受 → 下一章上下文，全程没有额外提取请求。这只证明操作流程可验收；[历史一次调用的失败试验](eval/AUTHOR-REVISION-RESULTS.md)、原始输出与细读失败判断未改写，真实写作质量仍未解决。本轮没有新真实模型调用、发布或部署。
